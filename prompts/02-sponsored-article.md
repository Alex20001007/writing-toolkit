# Prompt｜合作稿／業配稿／軟性置入

> 核心原則：**中立拆解 → 結論導向客戶**。可以偏的是框架、篇幅、語氣與結論；不能偏的是事實。

## 開工前要先定調的 6 件事

| 項目 | 要問清楚的 |
| --- | --- |
| 核心賣點 | 打什麼？選查證得過的具體優勢，而不是「首創」——首創常常查證不過 |
| 競品處理 | 點不點名？預設**不點名競品** |
| 開場 | 預設**不用宏觀行情開場**，從產業現象或使用者痛點切入 |
| 結構 | 客戶給的大綱如何排序（見下方範例） |
| FAQ / 版本 | 要不要 FAQ？單一版本還是多字數版本？ |
| 素材 | 客戶提供的截圖要不要放、放在哪一段 |

## Prompt 範本

```
這是一篇 {{客戶}} 的合作稿，產品是 {{產品名稱與一句話定位}}，大綱與素材由客戶提供（附件）。

寫作決策（已定案，請照做）：
- 核心賣點打「{{賣點}}」，不要寫成「首創」或任何查不到的第一。
- 不點名競品。
- 不用宏觀行情開場。
- {{不附 FAQ／附 FAQ}}；單一版本約 {{2500–3000}} 字。

結構：
1. {{產業現象與原因}}
2. {{相關生態的近期發展}}
3. {{同類新型態產品的簡介（不附截圖）}}
4. 切入 {{產品}} 的特色、解決的痛點、現有福利

寫法：用「教讀者怎麼分辨、怎麼避雷」的中立分析鋪陳，讓產品在分析中自然浮現為最佳解；誠實寫出產品的限制與風險。小標要有情緒和結論。

最後附：待跟客戶確認的事項清單。
```

## 交付後常見的修改方向（過去的實際回饋）

- 把通用教育內容（例：什麼是 CFD）縮短，改**連到站內舊文**，篇幅留給品牌可信度（監管、資金保護、獎項、贊助）與產品功能。
- 不要寫死「台灣用戶」，改成「{{品牌}} 的用戶」。
- 獎勵活動的機制要寫到讀者看得懂：門檻、累積規則、期限、出金條件。
