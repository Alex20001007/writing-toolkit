# 事實紅線檢查表（發稿前必跑）

> 深度文被抓到一個硬錯，毀的是整篇與媒體的公信力。把紅線前置，比事後勘誤便宜。

## A. 查無此事 / 似是而非

- [ ] brief 或口述裡「以為存在」的數據、報告、機構預估，實際查得到嗎？
  - 例：brief 假設某大行對某市場有規模預估，實查只有其他幾家券商的數字。
- [ ] 受訪者或客戶口頭給的數字，有沒有第三方報導可以對照？
  - 做法：查不到第三方佐證的口頭數字，文中寫成「據 OOO 分享」，並列入待確認。
- [ ] 規格數字（純度、比例、版本號）有沒有和官方文件不一致？
  - 做法：口述與官方規格不一致時，不確定就不寫，或確認後再寫。

## B. 不能寫反的事實

- [ ] 營運實體、母公司、品牌更名有沒有張冠李戴？（例：Matrixport 已更名 BIT）
- [ ] 「追蹤憑證」vs「直接持股」、「跟進者」vs「首創者」這類定性有沒有寫錯？
- [ ] 法條內容有沒有對照原文？（曾經把「穩定幣只能由銀行發行」「被歸類為商品」寫錯，對照條文後才更正）
- [ ] 同名不同物有沒有搞混？（例：兩個名字很像、彼此無關的錢包產品）

## C. brief 自相矛盾

- [ ] 行銷段和風險段的說法是否打架？
- [ ] 客戶不同素材之間的數字（用戶數、獎項數）是否一致？不一致就列入待確認，不自行挑一個。

## D. 交付時必附

1. **事實紅線摘要**：守住了哪些不能寫反的點
2. **待確認清單**：哪些要跟客戶／官方核實，發稿前再查一次
3. **來源清單**：可點擊連結＋日期
