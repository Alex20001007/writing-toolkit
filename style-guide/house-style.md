# 寫作風格指南（House Style）

> 從過去所有稿件的修改回饋整理出來的固定規則。下指令給 AI 或自己寫稿時，直接把這份貼進去當前提。

## 1. 語言與排版

- **繁體中文為主，專有名詞保留英文**：CLI、podcast、agent、TTS、OAuth、RWA、ticker 等不硬翻。
- **中文段落一律全形標點**：，。：（）？！。程式碼區塊、URL、檔名裡的標點維持半形不動。
- **文章內小標從 H3 開始**（部落格後台的 H1／H2 已被標題與版型佔用時）；原本的 H3 往下降成 H4。發稿前確認目標平台的層級規則。
- 交付格式：要貼進後台的稿件給 **Markdown 原始碼**。

## 2. 標題與小標（H2）——最常被退件的地方

**要慷慨激昂、帶情緒、帶結論**，讀者光看小標就知道這段的論點。

| ❌ 不要（平鋪直敘、AI 感） | ✅ 要（有情緒、有結論） |
| --- | --- |
| X 個地址 X 小時賺 X 元 | Robinhood 讓 Memecoin 造富神話再現，1 個地址在 7 小時獲利 120 萬美元 |
| 金庫參觀心得 | 「打開門你會覺得平平無奇」：一排貨架，一間就鎖住上百億美元 |
| RWA 的看法 | 葛大的 RWA 哲學：RWA，說到底就是 ReWArd |
| 拿金磚的感覺 | 一公斤黃金壓在掌心，原來「真實」可以這麼不真實 |

- 標題 / 小標寫法：**具體數字 + 反差或情緒 + 結論**。
- 主標通常給 3 個選項讓編輯挑。

## 3. 開場

- 30 字內要有鉤子：場景、反差、大數字或尖銳問句。
- **不要用宏觀行情開場**（「近期市場震盪……」這種讀者早就滑過）。
- 有時效性的題目，開場直接點出「為什麼是現在」（例：主席任期倒數三天交棒）。

## 4. 內容密度

- 偏好**精簡**：初稿常被要求「字數減少一點」。進階細節指向原始出處（GitHub、官方文件），文章本身不必包山包海。
- 但**使用情境、讀者能怎麼用**這類段落不要為了精簡砍掉，這是讀者最在意的部分。
- 新手向文章：只講「它做什麼」＋「最基本怎麼裝／怎麼開始」，再加一段**編輯觀點**（例：這個工具背後的策略意圖）。
- 文章結構偏好「**迷思 vs 真相**」「中立拆解 → 結論」這類有論點的軸線，而不是純歷史回顧或功能清單。

## 5. 活動／社群宣傳文

- 用**能量感長文**：emoji 段落標記、Web3 社群語言（BUIDL、組隊、現場開發）、結尾一個號召行動的 CTA。
- 不要短短一則推文了事。
- **獎金池不大時，不要拿獎金金額當開頭鉤子**，改以活動本身與開發體驗開場。

## 6. 給老闆／內部看的說明文件

固定結構，**不要寫得很虛**：

1. 概述（最多兩句，不鋪陳）
2. 問題
3. 解法
4. 功能說明（寫系統「做什麼」，不是畫面「長怎樣」）
5. 目前狀態

需要給主管快速看的文件：**摘要表格放最上面**，細節放後面，「簡單容易讀」優先。

## 7. 避免「AI 感」

- 標題、開頭、觀點這些最代表媒體立場的部分，由人定調；AI 負責研究、初稿、整理。
- 少形容詞，多具體例子、人名、數字、場景。
- 引用別家報導一律改寫並註明出處，不整段搬。

## 8. 事實與合規（詳見 `checklists/`）

- 現在式的數字、職位、法規一律查證、標出處與日期。
- 合作稿可以偏向客戶的是框架與結論，**不能偏的是事實**。
- 金融／CFD／交易所題材：不得出現保證獲利、穩賺、低風險、被動收入等暗示，結尾加「非投資建議」。
